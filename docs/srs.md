# Спецификация требований к учебному трекеру задач

## Назначение и границы

Этот документ фиксирует требования к небольшому локальному CLI-трекеру задач на Python 3.12+. Целевая версия — учебный MVP, который работает без сервера и хранит задачи в `tasks.json`. Основание для требований — условные интервью из [requirements.md](requirements.md); их сценарии являются учебной симуляцией, а не реальными пользовательскими данными.

## Пользователи и среда

Основные пользователи — студент, которому нужно фиксировать личные учебные дела, и начинающий разработчик, который клонирует репозиторий и запускает программу локально. Преподаватель использует команды и README для демонстрации. Среда — Python 3.12 или новее, терминал и локальная файловая система. Приложение использует стандартную библиотеку Python и не требует доступа к сети.

## Функциональные требования

- **ФТ-01 (Must):** CLI принимает непустое название задачи и создаёт запись с уникальным ID.
- **ФТ-02 (Must):** команда списка показывает ID, название и состояние каждой записи; для пустого списка сообщает, что задач нет.
- **ФТ-03 (Must):** созданные и изменённые записи сохраняются в `tasks.json` и загружаются при последующих запусках.
- **ФТ-04 (Must):** команда завершения меняет статус задачи по ID на «выполнена».
- **ФТ-05 (Must):** неизвестная команда или некорректные аргументы вызывают краткое сообщение и справку CLI.
- **ФТ-06 (Should):** пользователь может изменить название существующей задачи, сохраняя её ID и статус.
- **ФТ-07 (Should):** пользователь может удалить одну задачу по ID; команда удаления должна быть явной.
- **ФТ-08 (Could):** список можно фильтровать по состоянию «активна» или «выполнена».

## Нефункциональные требования

- **НФТ-01 (Must):** на локальном файле с не более чем 1 000 задач команды списка и добавления завершаются не более чем за 1 секунду на учебном ПК.
- **НФТ-02 (Must):** программа запускается в Python 3.12+ без сторонних пакетов.
- **НФТ-03 (Must):** русские строки корректно кодируются и отображаются в UTF-8.
- **НФТ-04 (Must):** ошибка чтения/разбора `tasks.json` показывается пользователю; приложение не перезаписывает повреждённый файл автоматически.
- **НФТ-05 (Should):** README и встроенная справка объясняют базовые команды, формат названия и расположение файла данных.
- **НФТ-06 (Should):** для базовой работы не требуются сеть, удалённый сервис или учётная запись.

## Бизнес-правила и данные

- **БП-01 (Must):** у каждой задачи уникальный положительный целочисленный ID, который сохраняется при изменениях.
- **БП-02 (Must):** название после удаления пробелов по краям имеет длину от 1 до 200 символов.
- **БП-03 (Should):** команды изменения статуса, редактирования и удаления работают только для существующего ID; при неизвестном ID показывается ошибка, а файл не изменяется.
- **БП-04 (Won't в этом релизе):** массовое удаление задач не предоставляется. Правило включено в реестр требований для фиксации границы релиза и снижения риска потери данных; оно не является реализуемой функцией MVP.

## Интерфейсы

Взаимодействие выполняется через аргументы командной строки. Данные хранятся в JSON UTF-8 рядом с приложением в `tasks.json`. Точные имена команд, их параметры и тексты сообщений задаются реализацией и должны быть отражены в `--help` и README. В MVP нет сетевого API и графического интерфейса.

## Исключения и защита данных

Некорректные аргументы, пустое/слишком длинное название и неизвестный ID не должны изменять данные. Ошибки чтения или JSON-разбора должны завершаться понятным сообщением, при этом исходный файл сохраняется для ручного восстановления. Доступ к данным локальный; аутентификация и шифрование не входят в границы проекта, поскольку приложение не обрабатывает учётные данные или удалённые данные.

## Приёмка MVP

MVP готов, если обязательные сценарии добавления, просмотра, локального сохранения, отметки выполнения и справки выполняются на поддерживаемом Python; ID и ограничения названия соблюдаются; ошибки не приводят к автоматической потере данных; русские строки отображаются корректно. Требования производительности проверяются на локальном тестовом наборе до 1 000 записей. Should и Could могут быть выпущены следующими инкрементами без блокировки базового MVP.
