# Пользовательские истории и критерии приёмки

Истории относятся к пяти ключевым Must-функциям учебного CLI-трекера. Формат критериев — Given / When / Then. Численные пределы и правила соответствуют [requirements.md](requirements.md) и [srs.md](srs.md). Источниками пользовательского контекста служат условные интервью И-1–И-3, описанные в requirements.md.

## US-01 Добавление задачи

**Как студент, я хочу добавить задачу с названием через командную строку, чтобы быстро зафиксировать новое дело.** Связанные требования: ФТ-01, НФТ-03, БП-01, БП-02.

- **Given** приложение запущено с корректной командой добавления и названием длиной 1–200 символов после обрезки пробелов, **When** команда выполняется, **Then** система создаёт задачу с уникальным положительным ID и показывает подтверждение с этим ID.
- **Given** название пустое после удаления пробелов по краям, **When** выполняется добавление, **Then** система сообщает об ошибке и не создаёт запись.
- **Given** название превышает 200 символов, **When** выполняется добавление, **Then** система объясняет ограничение и не меняет файл данных.
- **Given** название содержит кириллицу, **When** задача добавляется и затем читается, **Then** текст сохраняется и отображается без искажённых символов.

## US-02 Просмотр списка

**Как студент, я хочу увидеть задачи, их ID и состояние, чтобы выбрать нужную запись для дальнейшего действия.** Связанные требования: ФТ-02, НФТ-01.

- **Given** файл содержит несколько задач, **When** пользователь запрашивает список, **Then** вывод содержит ID, название и состояние каждой задачи.
- **Given** файл существует и содержит пустой список, **When** пользователь запрашивает список, **Then** показывается понятное сообщение, что задач нет.
- **Given** файл содержит не более 1 000 корректных задач, **When** пользователь запрашивает список на учебном ПК, **Then** команда завершается не более чем за 1 секунду.

## US-03 Сохранение между запусками

**Как пользователь, я хочу, чтобы изменения сохранялись локально, чтобы продолжить работу после закрытия терминала.** Связанные требования: ФТ-03, НФТ-04.

- **Given** задача успешно добавлена, **When** приложение закрыто и запущено повторно, **Then** список содержит ту же задачу с тем же ID и названием.
- **Given** `tasks.json` содержит некорректный JSON, **When** запускается команда чтения или изменения, **Then** система показывает ошибку чтения и не перезаписывает файл автоматически.
- **Given** сохранение завершилось успешно, **When** команда возвращает результат, **Then** файл содержит валидный JSON с созданной или обновлённой записью.

## US-04 Отметка выполнения

**Как студент, я хочу отметить задачу выполненной, чтобы отличать завершённые дела от активных.** Связанные требования: ФТ-04, БП-03.

- **Given** задача с указанным ID существует и активна, **When** пользователь запускает команду завершения для этого ID, **Then** её состояние меняется на «выполнена» и сохраняется.
- **Given** ID не соответствует задаче, **When** выполняется команда завершения, **Then** система сообщает, что задача не найдена, и оставляет все данные без изменений.
- **Given** задача уже выполнена, **When** команда повторяется, **Then** система сохраняет корректное состояние и сообщает результат без создания дубликата.

## US-05 Понятная помощь при ошибке команды

**Как начинающий пользователь, я хочу получить подсказку при неизвестной команде, чтобы самостоятельно исправить ввод.** Связанные требования: ФТ-05.

- **Given** пользователь передал неизвестное имя команды, **When** CLI обрабатывает ввод, **Then** отображается сообщение об ошибке и перечень доступных команд или способ открыть справку.
- **Given** пользователь запрашивает справку, **When** CLI выводит `--help` (или эквивалент), **Then** справка показывает команды, обязательные аргументы и краткое назначение.
- **Given** была введена неизвестная команда, **When** она отклонена, **Then** содержимое `tasks.json` остаётся без изменений.
## Примечание к учебному заданию

Условные интервью не подтверждают фактическое мнение реальных пользователей. Для реального релиза сценарии и цитаты следует обновить по результатам бесед, затем пересмотреть приоритеты и критерии.
